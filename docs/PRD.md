# StockInsight PRD

## 1. 제품 정의

StockInsight는 개인 사용자가 종목 가격 흐름과 Google Trends 검색 관심도를 함께 보고, 저장한 종목과 키워드 분석을 반복적으로 복원/최신화할 수 있도록 만든 웹 애플리케이션이다.

현재 제품은 다음 영역으로 구성된다.

- 종목 분석
- 키워드 분석
- 키워드 분석별 종목 오버레이 비교
- 운영 대시보드

인증은 Supabase Auth를 사용하고, 사용자 데이터는 Supabase PostgreSQL과 RLS 정책으로 격리한다.

## 2. 제품 목표

- 사용자가 종목과 키워드를 사용자별로 안전하게 저장하고 다시 볼 수 있어야 한다.
- 종목 가격 데이터와 Google Trends 데이터를 같은 주간 축으로 비교할 수 있어야 한다.
- 키워드 이름 아래에 조건별 분석을 저장하고, 각 분석에 독립적인 종목 오버레이를 둘 수 있어야 한다.
- 조회 중, 실패, rate limit, 캐시 부재 상태를 사용자에게 명확하게 보여줘야 한다.
- 다운로드, 정렬, 삭제, 최신화 같은 반복 작업이 안정적으로 동작해야 한다.
- 관리자는 수집/저장 상태와 최근 데이터 이상 후보를 읽기 전용으로 점검할 수 있어야 한다.

## 3. 비목표

- 실시간 시세 스트리밍
- 투자 추천 또는 자동 매매
- 뉴스/커뮤니티 감성 분석
- 다중 사용자 협업
- 모바일 네이티브 앱
- 관리자 화면에서의 데이터 수정/운영 명령 실행

## 4. 핵심 사용자

- 종목과 키워드의 장기 흐름을 비교하려는 개인 사용자
- 반복 조회, 저장, 최신화, 다운로드가 중요한 사용자
- 로그인 후 자기 데이터만 관리하는 단일 계정 사용자
- 배포 상태와 데이터 수집 품질을 점검하는 운영자

## 5. 핵심 사용자 여정

### 5.1 인증

1. 사용자는 회원가입 또는 로그인한다.
2. 보호된 페이지에 접근하면 로그인 여부를 검사한다.
3. 미인증 사용자는 `/login?next=...`로 이동한다.
4. 로그인 후 원래 가려던 페이지로 복귀할 수 있어야 한다.
5. 인증된 사용자가 `/login` 또는 `/signup`에 접근하면 목적지 또는 홈으로 이동한다.

### 5.2 종목 분석

1. 사용자는 `/search`에서 티커 또는 회사명을 검색한다.
2. 앱은 Yahoo Finance 기반 종목 미리보기를 생성한다.
3. 사용자는 미리보기에서 상세를 확인하거나 내 종목으로 저장한다.
4. 저장된 종목은 `/stock-analysis`에서 다시 조회할 수 있다.
5. 종목 상세에서는 지표, 차트, 커스텀 차트, 테이블을 본다.
6. 필요하면 저장 종목을 최신화하거나 삭제한다.

### 5.3 키워드 분석

1. 사용자는 `/keyword-analysis/new`에서 키워드를 입력한다.
2. 앱은 `/keyword-analysis/search`로 이동한 뒤 Trends 조회를 시작한다.
3. 조회 중에는 로딩 UI가 보여야 한다.
4. 성공 시 트렌드 차트와 13주 이동평균/YoY 지표를 보여준다.
5. 실패 또는 rate limit 발생 시 빈 상태가 아니라 명확한 실패 UI와 재시도 동선을 보여준다.
6. 사용자는 키워드를 저장하고, `/keyword-analysis`에서 저장된 키워드를 사전형 목록으로 다시 볼 수 있어야 한다.

### 5.4 조건별 키워드 상세 분석

1. 사용자는 저장된 키워드의 상세 페이지로 이동한다.
2. 키워드 아래에는 region, period, search type 조건 조합별 분석이 존재한다.
3. 현재 저장 원본 분석 데이터는 5년 데이터이며, 화면의 기간 선택은 저장된 5년 데이터를 잘라 보는 view filter로 동작한다.
4. 사용자는 조건별 분석을 생성, 복원, 최신화, 삭제할 수 있어야 한다.
5. 키워드와 분석 목록은 사용자가 정렬할 수 있어야 한다.

### 5.5 오버레이 관리

1. 사용자는 특정 키워드 분석에 종목 오버레이를 추가한다.
2. 오버레이는 keyword_id가 아니라 analysis_id 기준으로 저장된다.
3. 같은 키워드라도 조건이 다르면 오버레이 목록은 분리되어야 한다.
4. 사용자는 오버레이를 정렬, 삭제, 최신화할 수 있어야 한다.
5. 오버레이 차트는 종목 raw price와 normalized price를 저장하고 복원해야 한다.

### 5.6 다운로드

1. 사용자는 종목 분석 또는 키워드 분석 결과를 Excel로 내보낼 수 있다.
2. 차트를 PNG로 저장할 수 있다.
3. 다운로드 데이터는 화면에 보이는 분석 기준과 일치해야 한다.

### 5.7 운영 대시보드

1. `ADMIN_EMAILS`에 포함된 사용자는 `/admin`에 접근할 수 있다.
2. 관리자는 Redis, Yahoo Finance, Supabase, Python Function 등 운영 상태를 확인한다.
3. 관리자는 저장 데이터 수, 최근 키워드 분석, 최근 오버레이, 이상 데이터 후보를 확인한다.
4. 관리자 화면은 읽기 전용이어야 한다.

## 6. 기능 요구사항

### F001. 인증 및 사용자 격리

- Supabase Auth를 사용한다.
- 사용자 데이터는 `auth.uid()` 기준으로 분리한다.
- 보호 페이지는 미인증 시 로그인 페이지로 보낸다.
- 보호 API는 미인증 시 401 JSON을 반환한다.

### F002. 종목 검색, 미리보기, 저장

- 사용자는 티커 또는 회사명으로 종목을 검색할 수 있다.
- 종목 미리보기는 Redis에 임시 저장한다.
- 사용자는 미리보기를 저장 종목으로 전환할 수 있다.
- 동일 사용자 기준 중복 종목 저장은 막아야 한다.

### F003. 종목 시계열 수집

- Yahoo Finance 기반 5년 주간 데이터를 수집한다.
- 주간 데이터는 마지막 완료 주 기준으로 정규화한다.
- open, high, low, close, volume을 저장한다.
- 한국 주식 `.KS`는 현재 지원하지 않는다.
- 데이터는 저장 후 재사용 가능해야 하며, 최신화 기능을 제공한다.

### F004. 종목 분석 UI

- 저장 종목 목록을 제공한다.
- 종목 상세 페이지를 제공한다.
- 지표 카드, 기본 차트, 커스텀 차트, 테이블 뷰를 제공한다.
- 주간 수익률, 13주 이동평균, 52주 YoY 계산 결과를 보여준다.

### F005. 키워드 Trends 조회

- Google Trends 기반 데이터를 조회한다.
- 지원 검색 타입은 WEB, IMAGES, NEWS, YOUTUBE, SHOPPING이다.
- 지원 지역은 GLOBAL 및 국가/지역 코드다.
- 조회 중 로딩 상태를 보여준다.
- rate limit과 일반 실패를 구분해 보여준다.
- Trends 조회 실패를 빈 성공 응답으로 숨기지 않는다.

### F006. 키워드 저장 및 목록

- 사용자는 조회 성공한 키워드를 저장할 수 있다.
- 키워드 이름은 공백 정규화 기준으로 중복을 방지한다.
- 저장된 키워드 목록을 사전형 인덱스와 함께 볼 수 있다.
- 키워드 목록은 정렬 가능해야 한다.

### F007. 조건별 키워드 분석

- 키워드 하나는 여러 keyword_analysis를 가질 수 있다.
- 분석 단위는 `(keyword_id, region, period, search_type)` 조합이다.
- 현재 생성되는 분석 원본 기간은 5Y로 고정한다.
- 분석은 13주 이동평균과 52주 YoY 지표를 포함해야 한다.
- 분석 목록은 정렬 가능해야 한다.

### F008. 오버레이 관리

- 분석별로 종목 오버레이를 추가할 수 있다.
- 오버레이는 analysis_id 기준으로 저장된다.
- 중복 종목 추가는 막아야 한다.
- 삭제, 정렬, 최신화가 가능해야 한다.
- 필터가 바뀐 상태에서 잘못된 분석에 오버레이가 저장되지 않도록 filter mismatch를 검증한다.

### F009. 다운로드

- 종목/키워드 분석 데이터를 Excel로 내보낼 수 있어야 한다.
- 차트를 PNG로 저장할 수 있어야 한다.

### F010. 운영 대시보드

- 관리자 이메일 기반으로 접근을 제한한다.
- 시스템 상태와 데이터 요약을 읽기 전용으로 보여준다.
- `SUPABASE_SECRET_KEY`가 없으면 현재 관리자 세션에서 조회 가능한 범위만 보여준다.

## 7. 데이터 모델 요구사항

핵심 저장 모델은 다음과 같다.

- `searches`
- `stock_price_data`
- `keywords`
- `keyword_analysis`
- `keyword_stock_overlays`
- `overlay_chart_timeseries`

운영 대시보드는 다음 view를 사용한다.

- `admin_recent_keyword_analysis`
- `admin_recent_keyword_stock_overlays`

legacy keyword 테이블은 확장하지 않고 제거 방향을 유지한다.

## 8. 품질 요구사항

기본 품질 게이트:

```bash
npm run typecheck
npm run lint
npm run build
```

추가 요구사항:

- 프로덕션 UI는 내부 에러 메시지를 그대로 노출하지 않아야 한다.
- 외부 API 실패를 빈 성공 데이터로 처리하지 않아야 한다.
- RLS와 API 인증 검증을 함께 유지해야 한다.
- 다운로드 데이터는 화면 상태와 불일치하지 않아야 한다.

## 9. 성공 기준

- 사용자가 종목 분석과 키워드 분석을 로그인 후 안정적으로 사용할 수 있다.
- 키워드 조회 성공/실패/제한 상태가 UI에서 분명히 드러난다.
- 사용자별 저장 데이터 격리가 유지된다.
- 분석별 오버레이가 조건 변경에 따라 섞이지 않는다.
- 배포 환경에서 `/api/trends` -> `/api/pytrends` 기반 Trends 수집이 동작한다.
- 운영자는 최근 데이터와 이상 후보를 `/admin`에서 확인할 수 있다.
