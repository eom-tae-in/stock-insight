## 3. 인증과 데이터 보존 경계

현재 인증 모드의 기능 차이는 새 화면 설계에서 반드시 드러내야 한다.
레거시 모드의 제품 페이지는 로그인 필요 상태이며 서버 셸도 사용자를 검증한다.
공개 조회처럼 보이는 주가 조회 페이지를 비로그인 사용 가능 기능으로 분류하지 않는다.
보호 API의 미인증 응답은401이고 관리자 화면은 권한이 없으면404다.
근거: `src/middleware.ts`, `src/server/app-shell-data.ts`, `src/app/(app)/admin/page.tsx`.

OIDC 모드는 로그인 후 `/trends-jobs`와 허용 작업/로그아웃 API를 제공한다.
기존 저장 API는501 `LEGACY_PATH_NOT_MIGRATED`, 기존 제품 페이지는 작업 화면으로
이동한다. 이 모드에서 저장 종목·키워드·관리자 화면을 제공한다고 표시하면 안 된다.
`/signup`과 `/set-password`는 로그인으로 이동한다. 공급자 가입·비밀번호 관리와
레거시 계정 매핑은 새 인증 이전 설계에서 명시적으로 해결해야 한다.
Supabase·Vercel은 대상 의존성이 아니지만 현재 남은 레거시 동작은 보존 대상이다.

## 4. 화면 상태의 설계 인수 기준

다음은 새 설계에서 필요한 상태이며 이번 문서 작업의 런타임 통과 주장이 아니다.

| 화면군         | 반드시 구분할 상태와 행동                                                                                                  |
| -------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 검색·저장 목록 | 초기 빈 목록, 검색 결과 없음, 필터 결과 없음, 로딩, 오류, 저장 중·중복 저장, 오래된 데이터; 필터 초기화와 최초 추가를 구분 |
| 상세·차트·표   | 데이터 없음, 최소 주수 부족, null/0/양수/음수, 시리즈 비활성 이유, 기간 전환, 가로 표 스크롤, 전체 파일 내려받기 중/실패   |
| 편집·삭제      | 선택 없음/전체/일부, 취소, 확인, 처리 중, 실패·부분 성공, 완료; 중복 요청 방지와 초점 복귀                                 |
| 비교·분석      | 연결 없음, 임시 비교, 저장 연동, 조건 전환, 갱신 중·실패, 부모/소유 데이터 없음                                            |
| 인증·운영      | 로그인 실패, 만료·재인증, 가입/설정 모드 차이,401/404/501/503; 실제 미이관 기능을 성공처럼 표시하지 않음                   |

모바일은 주요 행동의44px 터치 영역, 자연스러운 한글 줄바꿈, 차트 축·표 데이터

reduced-motion·light/dark도 공통 상태에 포함한다. 색·글꼴·수치 토큰은 아직 새로 확정하지 않는다.

## 5. 새 화면 구조 제안과 미확정 사항

제안: 주 탐색을 관심 종목·키워드 분석으로 유지하고 각각 목록 → 조회 → 저장 상세의
흐름을 일관되게 구성한다. 검색은 조회의 진입 행동, 표는 상세의 보조 보기로 둔다.
비동기 작업은 OIDC 제공 범위에서만 노출하고 관리자는 권한별 보조 진입으로 둔다.
홈을 사용자 요약 화면으로 전환할지는 실제 콘텐츠와 우선순위를 확인한 뒤 결정한다.
이 제안은 URL 폐기·새 대시보드 구현·기존 시각 스타일 승인으로 해석하지 않는다.

다음 결정은 화면 구조, 핵심 행동 우선순위, 모바일 탐색, 홈의 역할,
시각 방향과 디자인 토큰이다. 이를 `DESIGN.md`의 새 계약으로 확정한 뒤
primitive 상태 검증과 작은 제품 화면 구현 단위로 진행한다.
이슈 #58 상세 갱신·삭제 구현은 미커밋으로 보존하며 채택 여부를 따로 결정한다.
PR #60의 규칙·상태 문서 경량화는 별도 미병합 작업이다.

## 6. 이번 실행의 증거와 한계

- 제품18개·개발6개 경로를 실제 `page.tsx`에서 확인했다.
- 이번 문서는 소스 조사이며 저장 DB 화면·실제 수집·전체 스택 검증이 아니다.
- Docker·DB·RabbitMQ·Keycloak 검증은 사용자 지시로 보류하며 Actions는 추가하지 않았다.
- 원래 #58 트리에서 재개 방향을 확인하기 전에 공통 삭제 창의 한글 줄바꿈·44px 높이를
  수정했다. 미커밋으로 보존하며 이 문서 PR에는 포함하지 않는다.
- 원래 트리의 `npm run check` 최초 실행은 포맷 정렬 오류로 실패했다.
  최소 정렬 수정 후 재시도1은 타입·린트·포맷·110개 파일685개 테스트를 통과했다.
- 원래 트리의 상세8개 fixture 화면 조합은 종료 코드0과 cleanup을 통과했다.
  증거는 `stock-insight-ui5e-Cq97AH`다. 독립 시각 검토를 재실행하지 않았으므로
  #58의 이전 REVISE를 승인으로 바꾸지 않는다. 새 설계 검증으로도 분류하지 않는다.
- 문서 포맷·경로 목록·근거 경로·diff 검증 결과는 PR에 기록한다.
- 컨텍스트 사용률은 환경에서 제공하지 않아 확인 불가다.
