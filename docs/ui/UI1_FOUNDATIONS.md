## 1. 변경한 화면과 대응 Figma 프레임

전역 토큰·글꼴은 기존 모든 화면에 적용된다.
직접 변경한 표현은 테마 아이콘·기존 계정 메뉴와 OIDC 사용자 이름의 화면 모드·차트 색 참조다.

| 테마 아이콘·화면 모드 선택                   | 상태·공유·계정 패턴 `15:2366`                         |

Figma Foundations·계정 패턴·OIDC 로그인 캡처를 읽고 비교했다.
원본 글꼴은 대체 표시이므로 구현은 명세의 Pretendard를 우선한다.
로그인의 좌측 소개·샘플 차트와 우측 로그인 패널 등 레이아웃은 UI-9에서 구현한다.
이번 단계에서 프레임 전체의 픽셀 일치를 주장하지 않는다.

## 2. 바뀐 동작과 유지한 동작

D2: 기본값 system, 시스템 색상 추종, light/dark만 사용한다.
상단 아이콘은 해석된 모드의 반대를 선택한다. 기존 계정 메뉴와 OIDC 사용자 이름 메뉴에 시스템/라이트/다크
세그먼트를 추가했다. 저장된 `calm`은 `system`으로 이전하고 기존 클래스도 제거한다.
고정 모드와 system 선택은 next-themes의 브라우저 저장 방식을 그대로 사용한다.
키보드로 메뉴 열기·화살표 선택·Esc 포커스 복귀를 검사했다.

인증·권한·OIDC 세션·CSRF·BFF·API·계산·정규화·저장·최신화·삭제·정렬은 유지한다.
작업 요청·폴링·늦은 응답 무시·추정 진행률 금지·상태 문구·aria-live·role=alert도 유지한다.
PNG 배경·파일명·pixelRatio와 Excel 계약은 변경하지 않았다.
공유 이미지용 .light 범위와 dark: 제외 토큰만 준비했다. D3 내보내기는 UI-9다.

### 실패와 복구 기록

1. `npx vitest run src/components/providers/theme-provider.test.tsx src/components/shared/theme-toggle.test.tsx src/components/auth/user-menu.test.tsx`
   첫 실행: 5개 실패, jsdom에 window.matchMedia가 없어 제품 검사 전에 실패.
   환경을 제공한 두 번째 실행: 1개 실패, 이전 클래스가 `calm light`로 남음.
   next-themes 부모 effect가 제거된 클래스를 다시 붙이는 원인을 확인하고
   system 전환 후 effect에서도 제거하도록 최소 수정. 복구 실행: 3개 파일 11개 통과.
2. `npm run check`와 `WEB_AUTH_MODE=oidc npm run build`의 첫 실행:
   DropdownMenuContent 공개 타입에 onOpenAutoFocus가 없어 TS2322·TS7006 발생.
   지원되지 않는 prop을 제거하고 선택 컴포넌트의 mount effect로 포커스를 이동.
   수정 후 두 명령 모두 통과했다.
3. `npm run test:web-oidc` 첫 실행: CSS 최적화의 `#fff`와 검사의 `#ffffff`
   문자열 차이로 실패. popover 검사를 계산된 RGB 색상으로 바꾼 두 번째 실행 통과.
   테마 검증 모듈 분리 후 재실행도 통과했다.
4. 캡처에서 작업 차트의 다크 축 기본 회색을 확인해 색 토큰을 연결하는 과정에서
   `npm run check`가 중복 tick prop(TS17001)을 검출했다. 중복 prop을 제거한 다음 실행은 통과했다.
5. OIDC 화면 모드 메뉴를 추가한 브라우저 검증에서 sr-only input 직접 클릭이
   보이는 label에 가로막혀 timeout으로 실패했다. 강제 클릭 대신 메뉴가 제공한
   선택값 포커스에서 화살표로 이동하는 실제 키보드 경로로 수정한 다음 실행은 통과했다.
6. 캡처 직접 검토에서 메뉴의 fade-in 도중 촬영된 불완전 증거를 발견했다.
   제품 코드는 변경하지 않고 메뉴를 연 후 애니메이션 종료와 opacity=1을
   확인하도록 검증 도구를 수정해 전체 캡처를 다시 생성했다.

해결한 실패를 숨기거나 검사를 약화하지 않았다. 남은 복구 오류는 없다.
동일 검증 두 번 실패 시 원인 조사·최소 수정 후 복구 검증을 수행하는 규칙을 적용했다.
위 1번의 복구 검증은 통과했으며, 복구 검증까지 실패한 상태에서 개발을 계속한 경우는 없다.
Node fixture의 기존 MODULE_TYPELESS_PACKAGE_JSON 경고는 남아 있다.

추가로 발견한 기존 문제: 차트에 hsl(var(--...)) 참조가 남아 있었다.
기존 oklch에도 맞지 않았으며 새 HEX 값에도 맞지 않아 var(--...)로 교체했다.
그리드는 chart-grid, 축·툴팁은 의미 토큰을 참조한다.

명세와 지시서 차이: 명세 §1.1은 0·결측을 text/secondary,
지시서 D7은 text/tertiary로 지정한다. 지시서를 우선하도록 DESIGN.md에 기록했고
실제 등락 컴포넌트 적용은 UI-2 이후다.

색이 바뀐 시리즈 버튼에 흰 글자를 그대로 쓰면 대비가 낮아져 선택 표면·글자를
중립 토큰으로 변경했다. 종목 차트의 표시 점은 시리즈 색을 유지한다.
open/high/low는 명세에 개별 색이 없어 기존 시리즈 구분을 유지하며 series-a/b/c에 연결했다.
YoY 단일 시리즈는 up을 쓰고 양수/음수 분리와 차트 구조는 D7/D1 단계에 남긴다.
기존 컴포넌트의 모든 blue/cyan/slate/amber 유틸리티를 이번에 일괄 교체하지 않았다.
화면별 UI-5~UI-9에서 명세의 의미 색으로 바꾼다.

기존 대형 차트 파일에는 색 참조·표현만 수정하고 폴링·계산·구조 리팩터링은 하지 않았다.
테마 컨트롤·provider·검증 보조 모듈은 별도 책임으로 분리했다.
