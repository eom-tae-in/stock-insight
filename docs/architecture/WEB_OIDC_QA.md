브라우저의 OIDC와 Gateway는 fixture다. 실제 Keycloak·Java·PostgreSQL·
RabbitMQ 통합은 사용자 지시에 따라 #24에 남기며 전체 MSA E2E 통과로
분류하지 않는다. 운영 HTTPS 쿠키·실제 사용자 두 명의 소유권·클라우드 배포는
검증하지 않았다. 기존 Supabase/Vercel 검증을 다시 실행하거나 통과로 바꾸지
않았다.

## 실패와 해결

1. OIDC 서버 시작 시 기존 Supabase 설정 검사 실행: instrumentation 초기화
   경로를 모드별로 분리하고 OIDC 설정을 직접 검사하도록 수정했다.
2. Playwright 전용 브라우저 없음: PC에 설치된 Chrome을 사용하도록 수정했다.
3. 복구 검증도 이전 완료 문구를 읽어 세대 번호 2/3 불일치: 규칙대로 중단하고
   보고했다. 사용자 재개 지시 후 갱신 POST 응답과 새 세대의 완료 GET 응답을
   기다리는 방식으로 해결했다. 시간만 늘리거나 세대 검사를 제거하지 않았다.
4. 정적 분석의 타이머 소유 구조 지적: 단일 interval과 진행 중 요청 방지,
   명시적 disposer로 정리했다. 리뷰에서 추가 발견한 실패한 갱신 이후 이전
   폴링 지속은 동작 시작 시 disposer 호출로 수정하고 회귀 테스트로 고정했다.
5. 첫 화면 검토에서 모바일 한글 어절 분리와 resize 전 차트/중복 헤더 캡처:
   새 화면에 break-keep을 적용했다. 브라우저 캡처는 폰트·transition·SVG와
   컨테이너 폭 일치·두 프레임을 기다리고 GPU 캡처 결함을 피하도록 했다.
   수정 후 13개 검토 대상 캡처를 모두 다시 열어 차트·줄바꿈·헤더를 확인했다.

## 정적 분석과 남은 사항

React Doctor 0.9.17의 최종 기록은 오류 0개, 경고 9개다. 결과 원문은 로컬
`/tmp/stock-insight-26-react-doctor.json`에 있다. 다음과 같이 구분했다.

- SSR 테마 mounted 처리 2개는 기존 공통 컴포넌트의 hydration 동작이다.
  이번 수정은 신규 화면에만 44px 터치 크기를 전달하고 기존 동작을 유지한다.
- Recharts 지연 로딩·큰 작업 컴포넌트 2개는 성능/유지보수 권고다.
  차트만 별도 로딩하고 상태 hook을 추출하는 개선은 후속으로 남긴다.
- effect의 네트워크 요청 1개는 이 기능의 비동기 작업 폴링이다. 중복 요청을
  막고 abort/disposer로 취소하며 종료 상태의 폴링 중단을 실제 확인했다.
- busy 해제 1개는 이미 finally에서 처리한다. 실패 후 버튼 복구도 확인했다.
- 내부 로그인 a 링크 1개는 전체 페이지 재진입 동작이며 기능 실패는 아니다.
- Zod strict 호환 API 2개는 Zod 4에서도 사용 가능한 API다. 타입·프로토콜·
  UI·브라우저 파싱이 통과했다. 신규 스키마 helper로 바꾸는 권고는 남아 있다.

`npm audit`는 전체 의존성 42개(critical 1개 포함)를 보고했다. 강제 자동
업데이트나 Next.js 메이저 변경을 실행하지 않았다. 새 OIDC/Redis/ky와 React의
직접 취약점 항목은 없었고 Next.js의 잔여 항목은 PostCSS 전이 의존성이다.
전체 의존성 보안 정비 완료로 분류하지 않는다.
